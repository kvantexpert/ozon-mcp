# Attributes, словари и классификация

## 1. Зачем нужна классификация

Ozon карточка не является свободной JSON-структурой.

Связь:

```
description_category_id
        +
type_id
        ↓
актуальный набор attributes
        ↓
required / optional
        ↓
dictionary values
```

Поэтому сначала классификация, потом заполнение.

## 2. Эталонная категория

`description_category_id = 200001489`

Название:

**Цифровые товары**

`type_id = 971075562`

Название:

**Код активации офисного приложения**

## 6. Найденные, но не автоматически применяемые значения

Срок:

`970789268 = Бессрочный`

Он найден для:

- 9297 — Срок действия;
- 9777 — Срок активации.

Но найденное значение не является доказательством, что его надо ставить конкретному товару.

Территории:

- 689 = Россия;
- 690 = Россия; Германия; Финляндия;
- 691 = Россия; Германия; Франция; Великобритания;
- 727 = Россия, Египет, Китай;
- 971046686 = Россия (кроме территории Крыма).

Также не выбирать без подтверждения:

- 9294 — количество устройств;
- 11467 — издание;
- 4359 — конкретная версия Windows.

## 7. Search dictionary

Используется operation:

`ozon_search_attributes_dictionary`

Endpoint:

`POST /v1/description-category/attribute/values/search`

Минимальные параметры:

```json
{
  "description_category_id": 200001489,
  "type_id": 971075562,
  "attribute_id": 5162,
  "language": "DEFAULT",
  "value": "Windows",
  "limit": 100
}
```

`value` должен иметь минимум 2 руны.

## 8. Правило dictionary

Нельзя:

`текст → сразу запись`

Нужно:

`текст → поиск → dictionary_value_id → проверка → запись`

## 9. Лицензионные поля

Особый контроль нужен для:

- территория активации;
- территория использования;
- срок действия;
- срок активации;
- количество устройств;
- издание.

Эти поля могут описывать коммерческие условия продукта.

Если подтверждения нет:

**не заполнять.**

## 10. Физические поля

Для электронной поставки не следует автоматически заполнять:

- тип носителя;
- упаковку;
- количество носителей;
- размер упаковки;
- физические характеристики.

Заполнение «для полноты» хуже, чем корректно пустое optional поле.

## 11. Главное правило для AI

AI не должен считать список attributes вечным.

При новой карточке:

1. снова получить category;
2. снова получить attributes;
3. снова определить required;
4. снова искать dictionary values;
5. только потом строить payload.
